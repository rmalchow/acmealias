DNS-01, without the credentials

Certificates for domains whose DNS you keep exactly where it is.

Publish one CNAME, once. Every renewal after that is invisible to you — and we never ask for access to your DNS provider, because the design does not need it.

  • It speaks to what you already run

    The challenge API implements lego's httpreq protocol, so anything built on lego works unchanged — Traefik needs one provider line and no plugin. The acme-dns protocol is next, which is what cert-manager, acme.sh, certbot, Posh-ACME and win-acme already speak.

  • An API key reaches exactly one thing

    A key carries grants, not a role: this action, on this object, and nothing adjacent. Give a staging host a key that can answer for staging and it cannot touch production — not because it is asked not to, but because there is no grant that would let it. Add an address range and an expiry and the key stops being a permanent secret.

  • Every challenge is on the record

    Who published a value, whether a certificate authority actually came and asked for it, from which address, how many times, and whether the validation completed. DNS-01 normally fails silently and you find out when a certificate expires; here the answer to did it work is a row you can read the same minute.

The whole integration, and how to check it

Two commands. The first is the record you publish once; the second is what we answer while a certificate authority is asking, and nothing at all when one is not. 

$ dig +short _acme-challenge.shop.example.com CNAME
shop-example-com.acmealias.com.
# published once, by you. Never changes again.

$ dig +short shop-example-com.acmealias.com TXT
"3sT4kQ9x_LbW2vPd8nZmR1cYhE0aJfKu6iGtOs5A"
# answered only while a validation is in flight,
# then withdrawn. Ask again tomorrow and it is empty.

Your DNS provider keeps every other record. We can answer one name, and it is a name that exists for this and nothing else.

Why a CNAME and not an API token

Handing a certificate tool your DNS credentials gives it the power to change every record you have, in order to change one. The alias model gives away exactly one thing: the right to answer one name that exists for this purpose alone.

What this is not

  • We do not host your DNS

    Your zone stays with whoever runs it now. We are authoritative for one name per domain, inside our own zone, because you pointed a CNAME at it.

  • We do not issue certificates

    Your ACME client and your certificate authority do that, exactly as they do today. We answer the DNS question that stands between them.

  • We never hold a private key

    Not your certificate's, not your account's. Nothing we store could be used to impersonate you, because nothing we store is secret to you.
