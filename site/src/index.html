DNS-01, without the credentials

Certificates for domains whose DNS you keep exactly where it is.

Publish one CNAME, once. Every renewal after that is invisible to you — and we never ask for access to your DNS provider, because the design does not need it.

  • Integrate

    Works with what you use

    The challenge API implements lego's httpreq protocol — Traefik needs one provider line and no plugin. acme-dns is next, the dialect cert-manager, acme.sh and certbot already speak.

  • Isolate

    A key reaches one thing

    A key carries grants, not a role. A staging key cannot touch production because no grant would let it — and with an address range and an expiry it stops being a permanent secret.

  • Audit

    Every challenge is on the record

    Who published a value, whether a certificate authority actually came for it, from where, and whether validation completed. DNS-01 usually fails silently and you find out when a certificate expires.

Your client, configured once

The challenge is the only part that touches us, and in every one of these it is a few lines.

One provider line. The endpoint and credentials come from the environment.

certificatesResolvers:
  acmealias:
    acme:
      dnsChallenge:
        provider: httpreq

# HTTPREQ_ENDPOINT=https://api.acmealias.com/
# HTTPREQ_USERNAME / HTTPREQ_PASSWORD = your key

The acmeDNS solver is built into cert-manager. No webhook to deploy.

solvers:
  - dns01:
      acmeDNS:
        host: https://api.acmealias.com
        accountSecretRef:
          name: acmealias
          key: acmedns.json

certbot reaches us through an auth hook — the console gives you the script.

certbot certonly \
  --preferred-challenges dns \
  --manual-auth-hook /etc/acmealias/present \
  -d shop.example.com

Four environment variables from the credentials file, then issue as usual.

export ACMEDNS_BASE_URL="https://api.acmealias.com"
export ACMEDNS_USERNAME="..." ACMEDNS_PASSWORD="..."
export ACMEDNS_SUBDOMAIN="shop-example-com"

acme.sh --issue --dns dns_acmedns -d shop.example.com

The same provider Traefik uses, because Traefik is lego underneath.

HTTPREQ_ENDPOINT=https://api.acmealias.com/ \
HTTPREQ_USERNAME=... HTTPREQ_PASSWORD=... \
lego --dns httpreq -d shop.example.com run

One tls block, using Caddy's acmedns DNS module.

tls {
  dns acmedns {
    server_url https://api.acmealias.com
    username   {env.ACMEALIAS_USER}
    password   {env.ACMEALIAS_PASS}
    subdomain  shop-example-com
  }
}

Choose acme-dns as the validation method and give it the credentials from the console. win-acme remembers them for every renewal.

The AcmeDns plugin ships with Posh-ACME. Point it at the endpoint and pass the credentials from the console.

Add acme-dns as a credential in the UI, paste what the console gave you, and pick it on the certificate.

The whole integration, and how to check it

Two commands. The first is the record you publish once; the second is what we answer while a certificate authority is asking, and nothing at all when one is not. 

$ dig +short _acme-challenge.shop.example.com CNAME
shop-example-com.acmealias.com.
# published once, by you. Never changes again.

$ dig +short shop-example-com.acmealias.com TXT
"3sT4kQ9x_LbW2vPd8nZmR1cYhE0aJfKu6iGtOs5A"
# answered only while a validation is in flight,
# then withdrawn. Ask again tomorrow and it is empty.

Your DNS provider keeps every other record. That CNAME delegates exactly one capability — the right to answer one name, which exists for this and nothing else. A DNS API token delegates all of them: the power to change every record you have, in order to change one.

What this is not

  • We do not host your DNS

    Your zone stays with whoever runs it now. We are authoritative for one name per domain, inside our own zone, because you pointed a CNAME at it.

  • We do not issue certificates

    Your ACME client and your certificate authority do that, exactly as they do today. We answer the DNS question that stands between them.

  • We never hold a private key

    Not your certificate's, not your account's. Nothing we store could be used to impersonate you, because nothing we store is secret to you.
